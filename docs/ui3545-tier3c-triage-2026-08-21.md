## What actually failed (mechanism)

Test data (`cypress/utils/utils.ts`): `createMultipleStakeholders(2)` →
two faker full names; `createMultipleStakeholderGroups(2, list)` → group *i*
gets stakeholder *i* (one member each → "Member count 1").

`Member filter validations`:

1. `validSearchInput = group0.members[0].substring(0, 3)` → `"Eli"` (from
   *Elizabeth Hammes*). Applies the **Stakeholders** filter — a client-side
   text match over the joined member names
   (`stakeholder-groups.tsx:144-155`), so *both* groups match "Eli".
2. Expands group 0's row, asserts the description-list `dd` contains
   *Elizabeth Hammes* → passes (screenshot step 47).
3. `if (group1.members[0].indexOf(validSearchInput) >= 0) exists(group1.members[0])`
   → *Elijah Lowe* contains "Eli" → `exists("Elijah Lowe")`.
4. `exists()` looks for the text in the table. Member names are rendered
   **only inside an expanded row's `DescriptionList`**
   (`stakeholder-groups.tsx:310-323`); the columns are Name / Description /
   Member count, and the table is `expandableVariant: "single"` (line 116).
   The test never expands group 1's row, so the text can never be present.
5. `exists()`'s recovery path fires: `cy.visit("/")` + `cy.visit(currentUrl)`
   — a full reload that drops the (non-URL) filter and collapses every row —
   exactly the screenshot — then the final `expect(text).to.include(value)`
   times out after 8 s.

The branch is unsatisfiable whenever the two faker names are distinct and
name 1 contains the first three characters of name 0. Measured with the
repo's `faker@5.5.3` (200 000 sampled pairs): **0.74 %** → roughly one run
in 135 of this spec. (When the names don't collide, the branch is skipped
and the test passes; the intended assertion is clearly "group 1's *row* is
also shown".)
